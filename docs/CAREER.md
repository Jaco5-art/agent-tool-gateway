# 简历与面试表述

## 项目名称

权限感知的 Agent 工具网关与沙箱执行系统（个人项目）

技术栈：Python、OpenAI Agents SDK、MCP、Pydantic、E2B、SQLite。

## 简历三条

- 基于 MCP 与 OpenAI Agents SDK 构建权限感知工具网关，实现动态工具发现与调用时授权复核，结合用户权限、Agent 能力上限、任务范围及逐级收窄的委托链约束工具执行。
- 实现高风险操作审批与一次性执行凭证；接入 E2B 执行模型生成的 Python，仅传入授权数据，并记录审批关联、代码/数据摘要和沙箱执行证据。
- 完成真实模型与 E2B 联调；8 个预设越权调用全部被拒绝，10 次手工注入/干净对照模型运行未观察到越权执行；Windows 回归测试 218 项通过、1 项平台相关跳过。

## 一分钟介绍

我做了一个 Agent 工具网关，用客服工单、退款和订单分析展示模型调用业务工具时的权限控制。模型通过 MCP 发现当前可见工具，每次调用还会经过独立授权检查。退款需要审批和一次性凭证；模型生成的数据分析代码在 E2B 中运行，只拿到授权范围内的数据。最后可以通过本地页面查看身份、判定、审批和执行证据。我同时做了强制越权回放和真实模型实验，并区分两类结果：真实模型没有产生越权尝试，因此没有把模型拦截率写成 100%。

## 面试追问

**为什么隐藏工具后还要校验？** 工具可见性减少暴露，但调用入口仍可能接收到直接构造、过期或伪造请求，因此执行端必须重新判断。

**为什么需要一次性凭证？** 审批同意的是特定身份、参数和上下文中的一次执行。绑定这些条件并原子消费，可以限制参数替换和重复执行。

**MCP 与 E2B 分别做什么？** MCP 负责工具发现和调用协议；E2B 提供代码运行环境；本项目网关决定调用是否获准及哪些数据可被提供。

**项目局限？** 本地身份、模拟业务、手工小样本，未验证通用注入防御；审计不是防篡改系统，运行级追踪尚未覆盖全部模型调用。

不要表述为：企业生产部署、零逃逸、通用防注入、100% 模型攻击拦截率，或 219 个攻击用例。
